# v0.3.0-preview

[日本語版](v0.3.0-preview.ja.md) · [GitHub Release](https://github.com/albert-einshutoin/mockport/releases/tag/v0.3.0-preview) · [Distribution](../site/distribution.md) · [Published app trial](../site/app-trial.md)

This preview fixes the selected workflows added since [v0.2.0-preview](https://github.com/albert-einshutoin/mockport/compare/v0.2.0-preview...v0.3.0-preview). The six built-in adapters remain `workflow-compatible` for documented local flows. This release does not promote them to `provider-compatible`.

## Selected workflow improvements

- **Stripe and OpenAI authentication:** when `auth_required: true` is configured with a fake secret, ordinary API requests reject a missing or wrong key. This is opt-in and does not use a real provider key.
- **Stripe Checkout:** a valid payment request supplies an inline price item. A new Session starts `unpaid`; the bundled Node app retrieves it, accepts a signed completed webhook, retrieves the paid Session through the official SDK, and updates its order once. Replayed or invalid events do not add a second payment update.
- **OpenAI:** the bundled Python app checks ordinary Chat responses, Chat Completions SSE streaming, wrong keys, bounded 429 retries, and timeout/cancellation behavior. Chat response metadata and the requested terminal streaming usage chunk also allow the unmodified [LLM 0.36 CLI](../../examples/external-llm/README.md) to complete four technical cases: nonstreaming, streaming, wrong key, and key restoration.
- **Slack:** the local helper delivers one signed message event to the bundled app. The app verifies the signature and timestamp with the official Python SDK and replies with the official WebClient in the same channel and thread. Tampered or old events do not produce a reply.

The [app trial guide](../site/app-trial.md) uses the published image, a fixed sample source, and `PUBLISHED_FLOWS=all`. The LLM runner has a separate fixed lock and model configuration. These verify selected application flows without real payments, provider credentials, Slack workspace traffic, or AI inference.

## Migrate from v0.2.0-preview

1. Update versioned Docker references, generated Compose files, and binary downloads to `0.3.0-preview`. `mockport init` now generates that image tag; use `--force` only if replacing your existing files is intentional. `latest` follows main and can change independently. Use the [versioned image and recorded digest](../site/distribution.md) for reproduction.
2. If enabling `auth_required` for Stripe or OpenAI, configure a distinct fake `fake_secret` and send that key in ordinary requests. Missing or wrong keys now fail. The default remains opt-in.
3. Stripe Checkout Session creation now starts `unpaid`. Supply a valid inline price item for a payment request; deliver the signed completion event before asserting paid business state. An empty-body Checkout example is only a Mockport demo, not a valid provider payment request.
4. OpenAI Chat Completions supports SSE streaming. Mockport Responses `stream:true` is unsupported and returns `501` / `mockport_unsupported_responses_stream`, including when `stream_success` is selected. Use nonstreaming Responses or the documented Chat path.

## Known limits

Compatibility applies to the selected workflows above, not every provider endpoint or official SDK call. State is in memory and is cleared on restart. Chat text and usage are simulated; usage counts are fixed and measure neither actual tokens nor cost or response quality. Responses streaming remains unsupported. Slack covers one message event and thread reply; parent/thread retrieval, other events, Block Kit, and real workspace delivery are outside this flow. The LLM 0.36 connection is a technical test; first-time user onboarding, another app's continued use, and product demand are unverified. See [limitations](../site/limitations.md) and the [support matrix](../site/support-matrix.md). Homebrew and npm remain unpublished distribution channels.
