# v0.3.0-preview 日本語版

[English](v0.3.0-preview.md) · [GitHub Release](https://github.com/albert-einshutoin/mockport/releases/tag/v0.3.0-preview) · [配布](../site/distribution.ja.md) · [公開アプリ試用](../site/app-trial.ja.md)

[旧 v0.2.0-preview からの差分](https://github.com/albert-einshutoin/mockport/compare/v0.2.0-preview...v0.3.0-preview)を固定した版です。6つの内蔵adapterは文書化されたローカルフローに対する`workflow-compatible`の範囲を維持します。`provider-compatible`への昇格は含みません。

## 選択したアプリフロー

- **Stripe・OpenAI認証:** `auth_required: true` と偽の`fake_secret`を設定した場合、通常APIリクエストの欠落・誤キーを拒否します。実キーは不要です。
- **Stripe Checkout:** 有効な決済リクエストにはinline price明細を指定します。Sessionは作成時`unpaid`で、Nodeサンプルアプリが取得し、署名付き完了Webhookを受け、公式SDKでpaid状態を再取得して注文を一度だけ更新します。重複・不正イベントでは追加更新しません。
- **OpenAI:** Pythonサンプルアプリが通常Chat応答、Chat Completions SSE、誤キー、上限付き429再試行、timeout・キャンセルを確認します。Chatのmetadataとstream終端のusage chunkにより、無変更の[LLM 0.36 CLI](../../examples/external-llm/README.md)でも非streaming・streaming・誤キー・キー復元の4ケースを技術的に接続しました。
- **Slack:** ローカルhelperが署名付きmessage eventを送ります。アプリは公式Python SDKで署名と時刻を検証し、公式WebClientで同じchannel・threadへ返信します。改ざん・古いイベントでは返信しません。

[公開アプリ試用](../site/app-trial.ja.md)は公開image、固定sample source、`PUBLISHED_FLOWS=all`を使用します。LLM runnerは別の固定lockとモデル設定を使用します。実決済・実provider鍵・実Slack workspace・AI推論は行いません。

## v0.2.0-preview からの移行

1. Docker参照、生成Compose、binary取得先を`0.3.0-preview`へ更新してください。`mockport init`の生成imageも更新済みです。既存ファイルを意図して置き換える場合だけ`--force`を使います。`latest`はmainを追う可変タグです。再現には[版付きimageと記録したdigest](../site/distribution.ja.md)を使います。
2. Stripe・OpenAIの`auth_required`を有効にする場合は別々の偽`fake_secret`を設定し、通常リクエストにそのキーを送ります。欠落・誤キーは失敗します。既定ではopt-inです。
3. Stripe Checkout Sessionは作成時`unpaid`です。有効なpayment requestにはinline price明細を渡し、署名付き完了イベントの後で業務上のpaid状態を確認します。空bodyのCheckout例はMockport専用デモで、providerの有効な決済リクエストではありません。
4. OpenAI Chat CompletionsはSSE streaming対応です。MockportのResponses `stream:true`は`stream_success`指定時も`501` / `mockport_unsupported_responses_stream`を返します。Responsesの非streamingか文書化したChat経路を使ってください。

## 既知の制限

互換性は上記の選択フローに限り、全endpointやSDK呼び出しを保証しません。状態はメモリ内のみで再起動時に消えます。Chat本文とusageは模擬で、usageは固定値です。実token数・費用・回答品質の計測値ではありません。Responses streamingは未対応です。Slackは一つのmessage eventとthread返信に限定し、親・thread取得、他のevent、Block Kit、実workspace配送は対象外です。LLM 0.36は技術接続の証拠であり、初見利用者の導入・別アプリの継続利用・需要は未検証です。[制限](../site/limitations.ja.md)と[対応表](../site/support-matrix.ja.md)も参照してください。Homebrew・npmは未公開の配布経路です。
